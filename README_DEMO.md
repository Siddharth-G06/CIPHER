# CIPHER Fraud Detection — 3-Minute Demo Script

This guide provides a step-by-step walkthrough to demonstrate the full capabilities of the CIPHER fraud detection pipeline, from real-time streaming to concept drift detection and automated model retraining.

## Prerequisites & Setup

1. **Start the Infrastructure (Kafka & MLflow)**
   Open a terminal in the project root and run:
   ```bash
   docker-compose up -d
   ```
   *Wait ~10 seconds for Kafka to initialize.*

2. **Start the Streamlit Dashboard**
   In a separate terminal, run:
   ```bash
   streamlit run app.py
   ```
   This will automatically open the dashboard in your browser (usually at `http://localhost:8501`).

---

## The 3-Minute Interview Demo

### 1. Tab 1: Live Monitor (0:00 - 0:45)
- Open the **sidebar** on the left.
- Under **Stream Controls**, set the delay to **100ms**.
- Click **▶ Start**. You are now streaming historical data through the Kafka producer into the Live Monitor in real-time.
- **What to show:**
  - Point out the **Auto-refreshing KPIs** (Total Processed, Total Flagged, Flag Rate).
  - Watch the **Live Transaction Table** populate. Mention the dynamic risk tier coloring (Critical, High, Medium, Low).
  - Highlight the **Rolling Fraud Rate** and **Processing Latency** charts updating live.

### 2. Tab 2: Review Queue (0:45 - 1:30)
- Navigate to the **🔍 Review Queue** tab.
- Select a transaction with a `CRITICAL` or `HIGH` risk tier from the dropdown.
- **What to show:**
  - Show the **Raw Features** and **Graph Features** expanders, explaining that graph features (like `card_degree_1h`) capture structural anomalies.
  - Point out the **SHAP Waterfall Plot** and the **Plain English Explanation** generated by the explainability module.
  - **Action:** In the Analyst Decision panel, select **CONFIRM_FRAUD**, adjust the confidence slider, add a note, and click **✅ Submit Feedback**. (This publishes an event to the feedback topic).

### 3. Tab 4: Drift Monitor (1:30 - 2:15)
- Navigate to the **🌊 Drift Monitor** tab.
- Explain that CIPHER uses both ADWIN (for rolling error rate) and PSI (for feature drift) to detect when the model degrades.
- **Action:** Scroll down to **Drift Simulation Controls**.
  - Select `high_value` drift.
  - Set the injection point to `0.7`.
  - Click **🚀 Run Simulation**.
- **What to show:**
  - Explain that this injects synthetic drift to simulate fraudsters changing their behavior.
  - Look at the **PSI Scores chart** and point out features hitting `Warning` or `Critical` thresholds.

### 4. Tab 5: Retraining Control (2:15 - 3:00)
- Navigate to the **🔄 Retraining Control** tab.
- Point out the **Feedback Statistics** and the **Decision Breakdown** pie chart (which should now include the label you submitted in Step 2).
- **Action:** Click **🔁 Manual Retrain**.
- **What to show:**
  - Wait for the spinner to complete. This kicks off the Champion/Challenger pipeline.
  - Show the **Last Retraining Info** panel. Did the challenger beat the champion? Was it promoted?
  - Scroll down to the **Retraining History** table to show the MLflow tracking integration.

## Teardown

When you're finished, stop the Streamlit app (`Ctrl+C`) and tear down the Docker containers:

```bash
docker-compose down
```
